# ADR 0003：共享 AI 主持 = 一次受限的工具调用循环，不引入 Agent 框架

状态：已采纳（2026-11-13）

## 决定

- 每个房间一个逻辑 Agent，由 `AgentService` 驱动：显式触发 → 排队合并 → 限流/额度检查 → 一次带工具的模型调用（最多 4 轮工具往返）→ 把回复发到群聊。
- 使用 Anthropic 官方 TypeScript SDK 的 Tool Runner（`client.beta.messages.toolRunner` + zod 工具定义）。不使用多 Agent 或编排框架。
- 模型藏在 `AgentModel` 接口之后；Agent 能做的事全部定义在 `AgentRoomPort`（由 `RoomRuntime` 实现）。
- 默认模型 `claude-opus-5-5`、`effort: low`，可通过环境变量改为更便宜的模型。默认开启服务端拒答回退（`fallbacks: "default"`），可关闭。
- Agent 不保存自己的长期记忆：每次调用都从服务端权威状态重新构建上下文。

## 理由

- PRD 要求的是「同一个主持人 + 受控工具」，一次工具调用循环就够；框架带来的抽象在这里没有对应的需求。
- 安全性来自结构而不是提示词：模型拿不到秘密（只给 `publicSummary`），也没有能绕过权限的工具（工具内部按最新状态重新校验，重要操作只能「提议」，由房主确认）。
- 调用是异步的后台行为，任何失败只会变成一条系统提示，满足「LLM 不阻塞游戏」与无 AI 降级。
- 接口隔离让 PRD 列为 P1 的「额外模型供应商适配」只需新增一个 `AgentModel` 实现。

## 现状与后续

- 已实现：@AI 与按钮触发、合并、限速、并发、每日额度、超时、失败降级、`suggest_game` 工具、用量记录。
- **尚未用真实模型联调**（开发环境没有可用密钥）；目前由脚本化的假模型覆盖编排逻辑。PRD §9.3 要求的真实模型试跑需在配置密钥后进行。
- 待实现：集体选择/投票类工具、偏好记录、阶段串场（含过期丢弃）、题目生成后台任务。每个新工具都要绑定房间/聚会/游戏段/回合，并在执行时校验。
