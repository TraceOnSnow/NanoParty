# ADR 0002：PostgreSQL + Drizzle；开发与测试用 PGlite；先写库后生效

状态：已采纳（2026-11-13）

## 决定

- 生产使用 PostgreSQL（Docker Compose 内置），ORM 用 Drizzle，迁移为生成的 SQL 文件，应用启动时自动执行。
- 未设置 `DATABASE_URL` 时使用 PGlite（Postgres 的 WASM 构建）：`pnpm dev` 和 `pnpm test` 不需要 Docker 或本机数据库。两条路径共用同一份 schema 和迁移。
- 游戏段的完整权威状态以 JSONB 存在 `segments.state`，每次被接受的操作在一个事务内落库，成功后才更新内存并广播。
- 成绩用只追加的流水表 `score_events`，总分由流水求和；`(segment_id, award_key)` 唯一。
- 服务重启后未结束的游戏段置为 `paused`，由房主确认继续（采纳 PRD §8.3 的建议默认）。

## 理由

- 「客户端看到的状态一定已持久化」直接满足 RES-03：恢复点就是最后一次成功的操作，不会出现已展示却丢失的结果。
- 流水 + 唯一键让结算天然幂等（SCORE-04），修正成绩时追加记录即可保留可追溯历史。
- 整段状态存 JSONB 而不是按游戏拆表：新增游戏无需改库，恢复就是读回一行。
- 每次操作一次事务写入，对朋友聚会的操作频率绰绰有余。

## 已验证

- 端到端测试在 PGlite 和真实 PostgreSQL 上都通过（含进程级重启恢复）；CI 中两者都跑。
