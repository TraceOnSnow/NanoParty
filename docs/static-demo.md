# 静态试玩版

不需要服务器、数据库和模型的一组静态文件，用来放在个人主页或任何静态托管上。它和正式版共用同一套规则模块（`packages/games`）和同一套游戏界面（`apps/web/src/games`），只是把「服务器」换成了浏览器里的一张桌子（`apps/web/src/demo/engine.ts`）。

## 两种玩法

| 入口 | 是什么 | 游戏 |
| --- | --- | --- |
| 线下开一桌 | 大家各拿各的手机，输入同一个房间号和人数。页面只出题、发身份，游戏由大家当面进行 | 适合这样玩的 17 款（`apps/web/src/demo/seed.ts`） |
| 看演示 | 一个真人 + 三个脚本玩家，主持念预先写好的台词，用来感受联机版的一局 | 脚本会玩的 10 款（`apps/web/src/demo/bots.ts`） |

### 线下开一桌怎么工作

房间号和人数是随机种子。每台手机用「房间号 + 第几题 + 自己选的身份」在本地算出该显示什么，所以：

- 同一个房间号的手机看到同一套题，一起点「下一题」就一起翻页；
- 需要保密的内容每台手机只显示自己那一份：按座位号发词和身份（谁是卧底、排排座、不撞词、问出秘密词），或者自觉选择队伍和队长/队员（暗号网格、密码传递）；
- 只该一个人看的内容（汤底、词卡、真答案、目标位置）默认盖着，点一下才翻开；
- 手机之间不传任何数据，页面也不记录进度：谁出局、谁得分由大家当面说了算。
- 房间的网址（`#r=房间号&n=人数`）可以直接发给别人，打开就在同一个房间。

只收录「出完题、发完身份就能靠嘴玩」的游戏。桌面状态一直在变的游戏（手牌、筹码、吃墩，例如别拿第六张、拒牌筹码、攒七张）不在这里，它们需要服务器。

## 构建与本地查看

```bash
pnpm demo:build      # 输出到 apps/web/dist-demo
pnpm demo:preview    # http://localhost:4173
node tools/browser/static.mjs     # 浏览器验收（需要上面的预览在跑）
node tools/browser/contrast.mjs   # 文字对比度测量
```

构建产物用的是相对路径，可以放在任意域名的任意子路径下。想在首页显示源码链接，构建时设 `VITE_REPO_URL`。

## 部署

- **任何静态托管 / 自己的服务器**：把 `apps/web/dist-demo` 整个目录交给 nginx、Caddy 之类的静态服务即可，不需要改写规则。
- **Vercel**：仓库根目录的 `vercel.json` 已写好安装命令、构建命令和输出目录，导入仓库即可（Framework Preset 选 Other，Root Directory 留仓库根目录）。Vercel 只能放这个静态版；正式版需要常驻进程、WebSocket 和数据库，放不上去。

### 本项目的线上部署

- 地址：<https://party.traceonsnow.com>（同一个站也能从 `nano-party.vercel.app` 访问）。
- Vercel 项目连着本仓库：推送到 `main` 自动构建并更新正式站；其他分支和 PR 各得到一个预览地址，不影响正式站。回滚在 Vercel 后台把上一次部署 Promote 回来。
- 域名在 DNS 里是一条指向 Vercel 的 CNAME，不经过 CDN 代理，证书由 Vercel 签发。
- 上线后可以对着公网地址跑一遍验收：`BASE=https://party.traceonsnow.com/ node tools/browser/static.mjs`。

导入时要注意两点：

- `vercel.json` 必须已经在被导入的分支上（默认是 `main`）。否则 Vercel 会根据根目录的 `Dockerfile` 和 `apps/web` 猜成「多服务」项目并给出一份 `services` 配置建议——不要采用，那会把正式版服务端当容器部署。
- 仓库在 `package.json` 里锁定了 pnpm 版本，Vercel 会按它安装，不需要额外的环境变量。

## 里面有什么、没有什么

- 只打包仓库里公开的内置题库（`bundledContent`），每条都带出处，首页「题库来源」里列出。`private-content/` 是服务端运行时才读的目录，不会进入这个构建。
- 没有密钥、邀请链接、聊天记录；页面不请求自己以外的任何地址（验收脚本 ST-09 检查这一点）。
- 事实类题目没有逐条核查，页面上写明了「仅供娱乐」。

## 和正式版不一样的地方

- **没有保密的服务器。** 正式版里游戏状态只在服务端，客户端只拿到自己的视图。这里一切都在本机算出来，懂技术的人打开开发者工具就能看到全部。所以它是试玩和线下助手，不是公平对局。
- **脚本玩家会偷看一处答案。** 估数字类游戏里，脚本为了报出像样的数字，会读本地状态里的正确答案再加上很大的误差。
- **主持不是模型。** 台词在 `apps/web/src/demo/script.ts`，只根据访客自己屏幕上已经公开的内容接话。
- **不保存进度。** 演示里刷新或关掉页面这一桌就没了（进行中会先提示）；线下开一桌刷新后回到第 1 题，重新选身份、翻到大家所在的那一题即可。
- **线下开一桌靠自觉。** 身份是自己选的，盖着的内容谁都点得开；它防的是不小心看到，不防故意偷看。
