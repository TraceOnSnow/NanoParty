# 海龟汤（soup）— 规则规格

方向：情境推理（「海龟汤」是通用的玩法名称）。题目为项目自写或改编自民间流传的情境谜题。实现：`packages/games/src/soup/game.ts`。

| 项目 | 规则 |
| --- | --- |
| 人数 | 3–8 人 |
| 内容 | 题库类型 `soup`：汤面 + 汤底 |
| 设置 | `rounds`（默认 2）；`playSeconds` 每碗汤限时（默认 600）；`pickSeconds` 选题时限（默认 60） |
| 汤主 | 每轮一名玩家轮流担任；负责选汤（看得到候选的汤面，可换一批或自己出）和回答 |
| 秘密信息 | 汤底只有汤主在选定后能看到；其他人在揭晓前的页面和网络数据中都没有汤底 |
| 提问 | 非汤主玩家提问（≤60 字），汤主回答「是 / 不是 / 无关 / 部分正确」；每人同时只能有一条问题或推理在等回答 |
| 推理 | 玩家提交完整推理（≤200 字），由汤主判对错；判对即揭晓 |
| 揭晓 | 有人答对、汤主或房主放弃、或时间到 |
| 计分 | 喝出汤的人 +3，汤主 +1；没人喝出不得分 |
| 跳过 | 进行中可投票跳过本碗，不计分 |
| 中途加入 / 断线 / 恢复 | 下一轮参与；问答记录与汤底随状态持久化；重启后暂停待房主继续，计时重新开始 |

**AI 汤主（未实现）**：回答是普通的游戏动作，将来可以让 AI 以汤主身份提交同样的动作，并以固定汤底为唯一依据作答。这属于 PRD §8.2「依赖模型实时裁判」的玩法，需要真实模型验证并另行批准；玩家汤主模式始终保留。

**待确认的默认值**：分值；是否限制提问次数；汤主能否把某个问题标为「关键」。

## VNext：AI 主持（`aiJudge = 1`）

| 项目 | 规则 |
| --- | --- |
| 人数 | AI 主持 2–8 人；真人主持 3–8 人 |
| 前提 | 服务器配置了模型。没有模型时开局会被拒绝并提示改用真人主持 |
| 选汤 | 轮流的选题人只看汤面选汤，不能自己出题（出题意味着知道汤底）。可以「让 AI 改编」：按主题只替换题目标注的可替换词，程序校验后才成为候选 |
| 提问 | 仍在左侧主面板。每条记录的状态：排队 → 判定中 → 已回答 / 失败。同一碗汤的问题按提交顺序逐条判定，后面的判定能看到前面已确认的回答 |
| 判定 | 是 / 不是 / 部分正确 / 无关 / 故事没说 / 问得不清楚。裁判只依据固定汤底和关键事实；不合格的输出按失败处理，不会编造判定 |
| 完整推理 | 由裁判判对错；判对即公布汤底，推理者 +3 |
| 提示 | 房主可以要一条提示，由裁判给出，不得包含关键事实 |
| 纠错 | 任何参与者可以标记「判错了」；房主可以让 AI 重判；房主也可以在确认剧透后查看汤底（这一碗不能再提问和推理）并手动更正。原判、更正人和理由都保留，并进入之后的判定上下文 |
| 失败与接管 | 判定失败可以重试（提问人或房主）。任何参与者可以在确认后接管为汤主：TA 看到汤底、不能再猜，之后由 TA 回答；其他人不会看到汤底 |
| 秘密信息 | 汤底只在服务端和裁判的提示词里。房间主持 AI、玩家视图、群聊、网络消息都不包含未揭晓的汤底 |
| 贡献记录 | 揭晓后显示每条关键事实由谁最先问出，仅供参考，不计分 |
| 结算 | 每一轮都当过真人汤主的人不参与名次（没有机会解谜） |
| 重启 | 判定中的问题在房主恢复游戏后重新排队，只判一次 |

题目格式（内容类型 `soup`）新增可选字段：`facts`（关键事实）、`fixed`（不能改的关键词）、`adaptable`（可替换的装饰词）、`basedOn`（母题 id）。
